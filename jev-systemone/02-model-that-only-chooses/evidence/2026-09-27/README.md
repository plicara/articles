Python 3.10 or newer, standard library only. `--figures` regenerates article Figures 4 and 6 from the same results. `extraction.jsonl` contains probabilities, original/revised labels, and peer-disagreement counts. `doom.jsonl` contains per-tic kills, health and episode boundaries for the later paired comparison. Neither ledger contains document text, extracted values, credentials or game images. The extraction ledger uses hashed task and document identifiers.

The public replay starts from these exported observations. Relabeling itself used the recovered ground truth, stored extractor outputs and text cache, plus the original and revised labelers. Those source inputs remain in the research workspace; `extraction-provenance.json` gives their hashes and the labeler/exporter hashes, and `source-provenance.json` identifies the source revisions. The per-field verdict files do not retain full HTTP request/response envelopes. These ledgers support arithmetic replay, not independent provider inference or a fresh model evaluation.

## Extraction protocol

We join saved first-pass probabilities to the 370-document ground truth and stored predictions. Retain non-null `ok` verdicts labelled OK/WRONG by the original labeler whose folded value (first 80 characters) matches the saved text layer using the original whitespace-tolerant presence rule. This produces 29,635 in-text verdicts. The presence heuristic and revised labeler have their own limitations; an in-text match does not prove that a checkbox or field was read correctly.

The revised labeler changes 292 original WRONG labels to OK and classifies 118 more as AMBIGUOUS. These are retrospective scoring-rule changes, developed after inspecting the benchmark. They are not untouched test-set labels or an independently adjudicated new gold standard. Ambiguous fields are excluded from revised metrics.

For each target field, eligible peers are all other systems returning a nonempty value for that document/field. Strings are casefolded and whitespace-collapsed. The target system never votes on itself. The strict-majority signal flags if the target string is supported by at most half of peers, including a tie. The uniform-peer signal is `disagreeing_peers / eligible_peers`, then averaged equally across target fields: this is an expected rate, not an integer count of caught fields. All three headline signals use the same fields. One revised WRONG field lacks a peer and is excluded from all three rows.

The comparison set contains 656 WRONG and 28,860 OK fields. The E4 fusion and E2 state comparisons each use their own common subset with all required responses present. Missing/error responses are excluded from those tables, not scored as successes; these conditional metrics do not represent full-corpus end-to-end reliability. Multiple fields and systems share documents, so the rows are correlated. No confidence interval or claim of independent trials is made.

## Doom selection

The selection follows the already recorded 23 September afternoon v5/control experiment: v5 run IDs 142839, 143123, 143410 and 143653; controls 144325, 144610, 144902 and 145150 (all prefixed `jev-20260923-`). Each arm has the same four seeds and 3,150 recorded tics per run. Kills are the sum of each episode's maximum cumulative kill count; deaths count completed episodes ending with nonpositive health. A final unfinished episode is not counted as a death. The data show v5 ahead on each seed, but four pairs do not establish a general effect.

The earlier higher-resolution grid runs are omitted from the current comparison because their summary metadata still labels them `v3`. Their existence and the original write-up are not sufficient to reconstruct an unambiguous configuration manifest. We do not relabel them silently.
